# 共用元件（第一階段）

共用 UI 保留既有 DOM、CSS、表單生命週期及業務行為。四個主分頁的呈現已移到 `src/pages/`，仍由 `HomePage` 使用原本的 `activeType` 切換，尚未增加路由。

| 目錄 | 責任 |
| --- | --- |
| `account/` | 登入、個人設定視窗 |
| `campaign/` | 團購卡片、精簡列、開團／參團／參與操作與評價視窗 |
| `purchase/` | 託購卡片、建立／編輯／報價／取消／評價視窗、訂單與配送資料 |
| `chat/` | 聊天室清單、團購聊天室、託購聊天室 |
| `navigation/` | 頂部列、手機與桌面導覽、分頁指示器、檢視模式切換 |
| `feedback/` | 確認對話框、通知、成功提示、下拉刷新指示器 |
| `media/` | 共用圖片瀏覽視窗 |
| `icons/` | 既有 SVG 圖示 |

## 使用界線

- 分頁狀態與 API 操作位於 `pages/` 的功能 hook／面板；`HomePage` 組合分頁與跨頁服務。
- 手機／桌面導覽由 `layouts/MainLayout.jsx` 呈現；滑動手勢、搜尋焦點及關閉選單的監聽位於 `layouts/useMainNavigation.js`。
- 元件原本已有的表單 state、effects 與外部 `key` 保持不變。移動元件不應順便修改重設或掛載時機。
- `purchaseRequestConfig.js` 提供「我的託購」分類設定，避免頁面透過 UI 模組匯入常數。
- `purchaseRequestUtils.js`、`campaignCardUtils.js` 收納本次抽出元件所需的既有共用函式；維持原判斷規則。
- `CampaignList` 提供「我的」與「合購」共用的列表、載入／錯誤提示、卡片／精簡列與分頁觸發點；所需資料、事件及 ref 由分頁 hook 經 `HomePage` 連接。`useCampaignFeed` 提供共用的請求生命週期，各分頁擁有獨立實例。
- 樣式仍由原本的 `App.css` 等檔案載入，不新增包裹 DOM 或調整 CSS 載入順序。

## 手動驗收

1. 桌面及手機切換「我的／合購／託購／詢問」，確認導覽、選取狀態與轉場。
2. 手機左右滑動切頁、垂直捲動及下拉刷新；開啟手機導覽後點擊外側關閉。
3. 開啟搜尋、輸入與清空關鍵字、切換搜尋範圍；確認焦點及返回操作。
4. 切換卡片／精簡模式、展開精簡列、開啟圖片瀏覽及個人資料。
5. 登入後檢查開團、參團、我的團購操作、通知入口及聊天室。
6. 託購檢查建立／編輯、配送資料選擇、報價／修改報價、取消確認、評價及訂單視窗；關閉重開確認表單狀態符合原行為。

第 5、6 項完整流程需要可用的後端、登入帳號及對應狀態的資料。四頁路由、狀態保存及驗收項目見 `src/pages/README.md`。
